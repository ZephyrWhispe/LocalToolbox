## 四、整合功能详解

### 4.1 工具箱

#### 功能说明

工具页提供 6 项本地文件/网络实用工具，全部离线可用：

1. **哈希校验**：对文件/目录计算 MD5 / SHA-1 / SHA-256（目录递归，4 线程并行，可取消），
   逐文件输出哈希、大小，并单独列出失败项；
2. **.md5 清单**：生成（`hash *path` 行式，兼容 `md5sum -c` 格式）与校验
   （逐行比对，缺失/篡改分别报因）；
3. **目录结构快照**：仅复制源目录的目录骨架（空目录也保留），支持正则过滤；
4. **文件清单导出**：导出目录内文件列表为 CSV（UTF-8 BOM，Excel 可直接打开），
   含相对路径、大小，可附 SHA-256 列；
5. **端口占用**：查询指定端口被哪个进程占用（PID/进程名），可结束该进程；
6. **二维码生成**：任意文本生成 PNG 二维码，前端可直接下载。

#### 使用方法

- 打开「工具」页，各卡片按需操作：
  - 哈希：点「选择文件/目录」→ 选算法 →「开始计算」；结果按行展示，失败项红色标注；
  - .md5：生成时选源文件/目录并选输出位置；校验时选 `.md5` 清单文件即出结论；
  - 快照：先选源目录、再选目标目录；
  - 导出：选目录，勾选「包含子目录 / 附带 SHA-256」；
  - 端口：输入端口号 → 查询，出现占用时可选「结束进程」（需确认）；
  - 二维码：输入内容 → 生成，右键图片可另存为。

#### 技术实现细节

- `app/core/tools.py`（纯标准库 + Pillow/qrcode）：
  - `hash_file(path, algo)` 分块（1 MiB）读流式计算，避免大文件全量载入内存；
  - `hash_paths(paths, algo, progress, cancel, workers=4)`：`ThreadPoolExecutor(4)` 并行，
    提供 `progress(cb)` 与 `cancel(flag)` 回调；取消时已提交任务自然结束，不中断他人；
  - `build_manifest(paths, algo)` / `verify_manifest(path)`：校验支持 `hash  path` 与
    `hash *path` 两种行式，分别按「文本模式/二进制模式」读取，缺失与哈希不符逐行报因；
  - `snapshot_tree(source, dest)`：`os.walk` 只建目录（`os.makedirs`），支持 `re` 过滤函数；
  - `export_file_list(path, include_sub, with_hash, algo)`：`csv.writer` + UTF-8 BOM（`utf-8-sig`），
    相对路径以所选目录为根；附带哈希时同样走分块计算；
  - `port_owner(port)` / `kill_pid(pid)`：调用 PowerShell
    `Get-NetTCPConnection -LocalPort <port>` 与 `Stop-Process -Id <pid>`（`subprocess` 捕获输出，
    无结果/失败均返回可读中文原因）；
  - `qr_png_data_url(text, size)`：`qrcode.QRCode(border=1)` 生成矩阵 → Pillow 放大到指定尺寸 →
    PNG → data URL；qrcode 未安装时返回 `None`，桥接层降级为中文提示。
- 桥接 `app/bridge/tools_api.py`（10 个 `tool_*`）：
  `tool_hash` / `tool_hash_pick` / `tool_manifest_pick` / `tool_verify` / `tool_snapshot` /
  `tool_export` / `tool_export_pick` / `tool_port_query` / `tool_port_kill` / `tool_qr`；
  文件/目录选择统一走 `window.create_file_dialog(webview.OPEN_DIALOG / FOLDER_DIALOG)`。
- 前端 `tools.js`：哈希/导出等耗时操作调用后端；清单行式预览、二维码下载等纯浏览器能力；
  全部交互返回统一 `{ok,data|err}` 契约，错误 Toast 展示。

### 4.2 截图标注

#### 功能说明

工具页提供「截图标注」工作区：

- **捕获**：全屏（多显示器全画布）或活动窗口（自动定位前台窗口矩形）；
- **编辑**：画笔、矩形、圆形、箭头、文字（4 档粗细/字号）、马赛克（拖拽框选后块采样模糊）、
  橡皮（destination-out）；撤销/重做各 12 步；可还原原图；超大图（>2500px）等比缩小编辑；
- **输出**：保存为 PNG（模板命名）、复制到系统剪贴板（Win32 CF_DIB）、另存；
- **历史**：按日期递归列出，可载入继续标注、资源管理器定位、删除。

#### 使用方法

1. 工具页 → 截图标注卡片 →「全屏截图」或「活动窗口截图」；
2. 画布上选工具（画笔/形状/文字/马赛克/橡皮）、颜色、粗细进行标注；
3. 「保存」写入默认目录（`~/Pictures/LocalToolbox/YYYY/MM/DD/`），
   「复制」把标注结果直接粘到任意应用；
4. 底部历史列表可点击加载历史图继续编辑，可定位/删除。

#### 技术实现细节

- `app/core/screenshot.py`：
  - `capture_full_png()`：`PIL.ImageGrab.grab()`（Windows 支持多显示器全画布）；
  - `capture_window_png()`：`ctypes` 调 `GetForegroundWindow` + `GetWindowRect` 取前台窗口
    矩形，再 `ImageGrab.grab(bbox=…)` 区域捕获；无前台窗口（最小化/全屏桌面上方）返回 `None`，
    桥接层给中文失败提示；
  - `save_png(png, shot_dir, label)`：文件名 `{日期}_{时间}_{清洗后标签}_{序号}.png`，
    按 `YYYY/MM/DD` 子目录落盘；`_safe_label` 剔除 `<>:"/\|?*` 等非法字符并限长；
    `_unique_path` 保证重名时追加序号不覆盖；
  - `png_data_url(png)` / `decode_data_url(url)` / `thumbnail_data_url(png, max_w=160)`：
    base64 编解码与历史缩略图；
  - `copy_png_to_clipboard(png)`：Pillow 解码 PNG → BMP 数据 → 构造 CF_DIB 位图
    （`BITMAPINFOHEADER` 40 字节头 + 自底向上 BGR 像素，stride 对齐 4 字节）→
    `ctypes.windll.user32` `OpenClipboard/EmptyClipboard/SetClipboardData(CF_DIB)/CloseClipboard`，
    **不依赖 pywin32**；
  - `list_history(shot_dir)`：`os.walk` 按 `YYYY/MM/DD` 递归收集，按文件名倒序（新在前）。
- 桥接 `app/bridge/screenshot_api.py`（8 个 `shot_*`）：
  `shot_capture(mode)` / `shot_save(data_url, label)` / `shot_copy(data_url)` /
  `shot_history()` / `shot_open(path)` / `shot_reveal(path?)` / `shot_delete(path)` /
  `shot_set_dir(path?)`；`shot_delete` 以 `realpath` 前缀校验限定在截图目录内，防越界删除；
  目录可经 `shot_set_dir` 改存并持久化到 `config.json` 的 `screenshot_dir`。
- 前端 `screenshot.js`：
  - 画布标注基于原生 Canvas 2D：形状用 `beginPath + stroke`、文字用 `fillText`、
    马赛克按 bbox 切块后 `drawImage` 局部缩放回填、橡皮用 `globalCompositeOperation =
    'destination-out'`；
  - 撤销/重做：两张栈各存 12 步 `dataURL`，出栈后 `drawImage` 恢复；
  - 缩放：原图宽高任一 >2500px 时等比缩到 2500 内编辑，保存时按比例还原坐标输出原尺寸。

### 4.3 剪贴板图片同步

#### 功能说明

剪贴板同步从纯文本升级为「文本 + 图片」双通道：

- **监听**：本机复制图片（截图工具、文件管理器 Ctrl+C 图片等）→ 自动同步到局域网设备；
- **接收**：远端图片 → 写回本机剪贴板（可直接粘贴）→ 落盘到
  `%APPDATA%/LocalToolbox/clipboard_images/` → 进历史；
- **历史**：图片条目带 160px 缩略图与落盘路径，点击可回贴到本机剪贴板；
- **回声抑制**：自己推出去的图片回来后自动跳过，不产生死循环。

#### 使用方法

1. 剪贴板页确保「同步」开关开启；
2. 任一端 Ctrl+C 一张图片 → 对端「剪贴板历史」出现图片条目（带缩略图）→ 点击条目回贴，
   或直接 Ctrl+V 粘贴到对端应用；
3. 历史条目可删除；图片 >2MB 时仅记本地历史，不推送（协议上限保护）。

#### 技术实现细节（`app/core/clipboard_sync.py`）

- **读取**：监听线程检测剪贴板序号变化且文本为空时，`GetClipboardData(CF_DIB)` 取 DIB 内存 →
  `_dib_to_png()`：解析 `BITMAPINFOHEADER`（宽/高/位深 24/32）→ 按 stride 对齐逐行
  `PIL.Image.frombytes(raw, "BGR"/"BGRX")` → PNG；上下颠倒（`h<0`）自动翻转；
  校验失败（非法尺寸/位深）安全返回 `None`，不影响文本通道；
- **推送**：沿用文本同一 TCP 行协议，消息 `kind=image` + base64(PNG)；
  `DEDUP_WINDOW=60s` 内相同哈希不重复推送；>2MB 本地历史 + 日志警告；
- **接收**：远端消息解码 PNG → 落盘（按 SHA-1 前 16 位命名，去重）→ 写回本机剪贴板
  （复用 CF_DIB 写入）→ 追加历史（`kind=image` + 路径）；
- **回声抑制**：接收写入的图片哈希记入 `_suppress` 集合，本机监听读到同哈希直接丢弃；
  本机产生的图片哈希不入 suppress，正常外推；
- **历史序列化**（`app/bridge/clipboard_api.py`）：`kind=image` 条目附带
  `thumbnail_data_url`（160px）与落盘路径；前端渲染缩略图，点击经 `clip_copy` /
  `clip_copy_path` 回贴（`copy_png_to_clipboard` 复用截图模块能力）。

### 4.4 文件传输：手动 IP 直连

#### 功能说明

设备发现依赖 UDP 广播，跨网段 / 广播被禁 / 多网卡场景下设备不在列表时，传输页提供
「手动发送（IP 直连）」：填目标 IP + 端口（默认 41893）直接发起传输。

#### 使用方法

传输页 →「手动发送（IP 直连）」→ 输入目标 IPv4（必填，格式校验）→ 端口默认 41893 →
「选择文件并发送」→ 弹系统多选文件 → 复用完整传输链路（确认/加密/进度/断点续传）。

#### 技术实现细节

- 仅前端改动（`webui/js/pages/transfer.js`），复用现有 `xfer_send(ip, port, paths, note?)`
  桥接方法与既有引擎能力，无新增后端状态；
- 前端校验：IP 格式正则（`\d{1,3}(\.\d{1,3}){3}`）、端口 parseInt 兜底默认值；
- 无浏览器/域名歧义：直接 TCP 直连，与发现列表发送完全同链路（含配对加密、断点续传）。

## 七、v2.4 全面审核修订（2026-09-09）

对全量代码（core/bridge/webui/测试）二次审核（质量/正确性/性能/安全/最佳实践），
修复 11 项明确缺陷（详见 [技术文档.md CHANGELOG v2.4](./技术文档.md)），关键结论：

1. **截图链路曾整体失效**：`_init_shot` 实例属性遮蔽同名方法，保存/历史/删除/定位/改目录
   全部 `NoneType not callable`（测试桩绕过初始化故漏检）——桥接 Mixin 的 `_init_xxx`
   不得缓存与方法同名的实例属性；
2. **64 位句柄截断**：Win32 ctypes 未声明 argtypes/restype，`GetForegroundWindow`/
   `GlobalAlloc/GlobalLock/SetClipboardData` 句柄截断为 32 位；已补齐并修复剪贴板
   失败路径句柄泄漏（原「OS 回收」注释有误）；
3. **DIB 解码方向**：Pillow raw orientation 实测为 -1=bottom-up 翻转、0/1=top-down，
   topdown（负高度）分支原解码颠倒，已修正为 `-1 if topdown else 0`；
