## 一、总体架构（v3.0）

UI 已从 PySide6/Qt 迁移为 **pywebview 6 + 原生 Web 前端**（系统 WebView 渲染，
无构建步骤），Python 核心模块全部保留复用。

```
main.py                       入口：创建窗口 + Bridge(js_api)
├─ app/bridge/                桥接层（聚合 Mixin，方法名「页面_动作」）
│   ├─ base.py                事件推送 emit()（未就绪自动缓冲）+ CLI 预填动作
│   ├─ bridge.py              聚合：app_info / devices_list / cfg_get / cfg_set
│   └─ *_api.py               各页面桥接（clipboard/shellmenu/share/web/ftp/
│                             scan/network/file/km/transfer/tools/screenshot
│                             + pan(网盘)/proxy(代理)【v3.0】）
├─ app/core/                  Python 核心（与 UI 解耦，可独立测试）
│   ├─ discovery.py           UDP 41890 设备发现（心跳广播 + advertise 扩展字段）
│   ├─ transfer.py            【P0-3 新增】文件传输引擎（TCP 41893）
│   ├─ clipboard_sync.py      剪贴板同步（TCP 41891）
│   ├─ km_share.py            键鼠共享（TCP 41892）
│   ├─ openlist.py            【v3.0 新增】OpenList 进程托管（WebDAV 15244）
│   ├─ webdav_client.py       【v3.0 新增】纯 stdlib WebDAV 客户端
│   ├─ v2ray_core.py          【v3.0 新增】v2ray/xray 核心托管 + 节点库
│   ├─ bindl.py               【v3.0 新增】GitHub Releases 二进制自动下载器
│   ├─ config.py              配置持久化 %APPDATA%/LocalToolbox/config.json
│   └─ …                      share/ftp/web/scan/network/file_manager/shell_menu/firewall
└─ webui/                     前端（经典 script 标签 + 全局 App 命名空间）
    ├─ index.html             壳：标题栏 / 导航 / 内容 / 设备面板 / 状态栏
    ├─ js/ui.js               DOM 构建、图标、Toast、模态框、脱敏、格式化
    ├─ js/bridge.js           App.call/tryCall/guardedCall + 事件分发
    ├─ js/app.js              导航路由、设备面板（拖拽/发送文件目标）、主题
    └─ js/pages/*.js          15 个功能页（每页 App.registerPage 注册；v3.0 新增 pan/v2ray）
```

**约定**
- js_api 方法名 `页面_动作`（如 `xfer_send`），统一返回
  `{ok:True, data:…}` / `{ok:False, err:"中文"}`；
- pywebview 6 **不支持 async def 的 js_api 方法**，全部用普通 `def`；
- 后台线程 → 前端事件：`self.emit(name, payload)` → `window.__push` → `App.dispatch`；
- 页面注册：`App.registerPage({id, title, icon, group, mount(el), show?, onCli(path)?})`，
  group ∈ 协作 / 共享服务 / **网盘与代理（v3.0 新增）** / 工具 / 系统（`app.js` GROUP_ORDER）。

**端口分配**

| 端口 | 协议 | 用途 |
|------|------|------|
| 41890 | UDP | 设备发现心跳（广播） |
| 41891 | TCP | 剪贴板同步 |
| 41892 | TCP | 键鼠共享 |
| 41893 | TCP | 文件传输（P0-3） |
| 15244 | TCP | 网盘挂载的 OpenList WebDAV 接口（v3.0，可配置） |
| 10809 / 10808 | TCP | v2ray/xray 核心 HTTP / SOCKS5 代理（v3.0，可配置） |

## 二、文件传输引擎（P0-3，本期新增）

### 2.1 需求
1. 局域网设备间点对点直传文件/文件夹，无需挂载或共享；
2. 大文件分块传输 + **断点续传**（中断后重发只传剩余部分）；
3. **SHA-256 整文件哈希校验**，确保内容完整；同名同哈希文件直接「秒传」跳过；
4. 接收端**逐次确认**（可选自动接收），可设置接收目录；重名文件自动改名不覆盖。

### 2.2 协议（每帧 = 一行 JSON + 可选二进制负载）
```
发送端 -> 接收端:
  {"type":"offer","tid":..,"id":..,"name":..,"files":[{path,size,hash}],"total":n}
  {"type":"begin","path":rel,"size":n,"hash":sha256}
  {"type":"chunk","bin":N} + N 字节原始数据        （分块 1 MiB）
  {"type":"end","path":rel}
  {"type":"cancel","reason":..}
接收端 -> 发送端:
  {"type":"accept","have":{rel:已有字节数}}        （断点续传依据；have=size 即秒传跳过）
  {"type":"reject","reason":..}
  {"type":"file_ok","path":rel,"hash_ok":bool,"skipped":bool}
  {"type":"file_fail","path":rel,"reason":..}
  {"type":"summary","ok":n,"fail":[...]}           （发送端发完半关闭写端，接收端 EOF 后回）
```

### 2.3 关键设计
- **设备发现联动**：心跳 beacon 增加 `file_port` 字段；设备卡片据此显示「文件」标签、
  出现「发送文件」按钮，并作为拖拽投放目标；
- **断点续传**：接收端以 `<final>.part` 保存未完成文件，accept 回已有字节数，
  发送端 `seek(offset)` 只传剩余；连接中断不删 .part，下次续传；
- **哈希**：发送端 offer 前预读计算整文件 sha256（可取消）；接收端落盘后回读比对，
  不一致回 `hash_ok:false` 并记失败；
- **防目录穿越**：接收端 `_safe_rel` 校验相对路径（拒绝 `..`、盘符、空段），
  文件只能落在接收目录内；
- **重名处理**：同名不同内容 → `name (1).ext` 顺序改名；同名同哈希 → 秒传跳过；
- **确认流程**：默认逐次确认（offer → 前端弹卡片 + Toast → 用户接收/拒绝，
  120 秒超时自动拒绝）；设置页/传输页可开「自动接收」；
- **取消**：任一侧均可取消，双方立即终止，.part 保留供续传；
- **进度推送**：`xfer_offer` / `xfer_progress`（0.2s 节流，含速率）/ `xfer_done` / `xfer_log`。

### 2.4 UI（「文件传输」页 + 设备卡片）
- 设备卡片：发送文件按钮（系统多选对话框）、文件拖拽投放
  （pywebview drop 事件取 `pywebviewFullPath`，仅 Windows 有效）；
- 传输页：服务状态（端口/防火墙放行按钮）、待确认请求卡、进行中列表
  （进度条 + 速率 + 取消）、历史 50 条、日志；
- 设置：接收目录（默认系统下载目录）、自动接收开关（存 config.json）。

### 2.5 安全边界
- 局域网明文传输，仅建议可信内网；配对 PIN / TLS 加密列后续版本（§五）；
- 默认逐次确认 + 接收目录隔离 + 路径穿越校验，三层防线。

## 三、剪贴板同步（已上线）

Win+V 式本机历史 + 局域网实时同步（文本，≤2MB/条）：

- 本机 `AddClipboardFormatListener` 实时监听，历史上限可配置（10–1000 条），内存保存；
- TCP 41891 长连接推送，sha1+时间戳去重、回声抑制防互发风暴；
- 发送/接收两个独立开关；手动添加 IP 兜底；
- 历史列表：搜索、点击回贴、脱敏显示（手机号/身份证/银行卡）；
- 右键菜单 `--clip` 支持 ≤2MB 文本文件导入剪贴板并推送。

## 四、键鼠共享（已上线）

一台电脑的键鼠实时「延伸」到局域网另一台（TCP 41892）：

- 控制端：低级钩子 `SetWindowsHookEx(WH_KEYBOARD_LL/WH_MOUSE_LL)` 截获输入转发；
- 被控端：`SendInput` 注入（绝对坐标归一化 0–65535，自动适配分辨率/多屏）；
- 热键切换（默认 `Ctrl+Alt+K`），单连接互斥，「允许被控制」显式开关；
- 不能作用于 UAC 提权窗口（系统安全边界）；
- **v2.9 扩展（T-03/04/05）**：多目标直连星型（一台控制端挂多台被控端、可切换）、
  鼠标滑出屏幕边缘自动切换目标（四方向邻居表配置）、`hello/welcome` 交换
  虚拟屏矩形与 DPI 实现精确映射；详见 [§十六](./功能设计文档.md)。

## 八、风险

- 杀毒/办公网安全软件可能拦截模拟输入与广播包 → 文档提示加白名单；
- Windows Defender 对未签名 exe 提示 → 与现状一致，不做签名；
- 某些笔记本网卡/驱动默认禁用 UDP 广播 → 发现失败时手动填 IP 兜底
  （文件传输亦可在传输页手动输入 IP:端口发送，预留）；
- pywebview 拖拽路径 `pywebviewFullPath` 仅 Windows 提供 → 与平台范围一致。

## 九、日志系统（新增）

统一日志框架 `app/core/logger.py`，覆盖系统运行状态、用户操作、错误异常与关键业务流程：

| 要素 | 实现 |
|------|------|
| 级别 | DEBUG / INFO / WARN / ERROR / FATAL（logging 的 WARNING→WARN、CRITICAL→FATAL 归一） |
| 基本字段 | `ts`（毫秒 ISO）、`level`、`logger`（模块）、`func`、`line`、`dev`（设备名，启动注入）、`pid`、`msg`；扩展字段 `event` / `tid` / `dur_ms` / `exc` |
| 格式 | 每行一条 JSON（`ensure_ascii=False`），一行一条，便于程序化解析（jq / 日志分析平台） |
| 分级存储 | `logs/app.log` 全量（5 MiB × 3 份轮转）+ `logs/error.log` 仅 ERROR/FATAL（1 MiB × 3 份） |
| 轮转 | `RotatingFileHandler` 按大小切割；Windows 上 rename 加 10 次重试（防杀软/索引器锁文件） |
| 异步防阻塞 | `QueueHandler`（队列满丢弃并计数 `dropped`，不阻塞主流程）+ 后台 `QueueListener` 消费写盘 |
| 运行时调级 | 设置页可切级别（`set_level`），不重启生效 |
| 查询分析 | 设置页「日志」卡片：级别选择、目录/文件大小、打开日志目录、查看 app.log；`log_status` / `log_set_level` / `log_open_dir` / `log_open_app` |

接入点：
- `main.py` 启动初始化 + `sys.excepthook` 未捕获异常记 FATAL（含堆栈）+ 退出前 `stop_logging()` 刷盘；
- `bridge/base.py` 自动记录全部 js_api 调用（INFO，不落参数值）、异常（ERROR + 堆栈）、
  慢调用（≥2000ms 记 WARN）；高频查询类（`_get_state`/`_list`/`app_info`/`cfg_get` 等）记 DEBUG 防刷屏；
- 核心模块：transfer / pairing / clipboard / km / discovery / scanner / share / firewall / drive /
  ftp_server / ftp_client / web_server / network_toggle / runner（命令执行 DEBUG）/ tray。

日志目录：`%APPDATA%/LocalToolbox/logs/`（app.log、error.log 及轮转备份）。

## 十、功能整合（v2.3）：工具箱 / 截图标注 / 剪贴板图片

|------|------|

### 10.2 截图标注（工具页）

### 10.3 剪贴板图片同步（剪贴板页升级）

- 监听：剪贴板 seq 变化且文本为空时，读 `CF_DIB` → BITMAPINFOHEADER 校验 → Pillow raw 解码（24/32 位、上/下颠倒）→ PNG；
- 同步：沿用同一 TCP 行协议，`kind=image` + base64；消息超接收端缓冲上限（base64 后）仅本地历史不回推；
- 接收：解码（IHDR 像素上限 5000 万，防解压炸弹）→ 写回本机剪贴板（复用 CF_DIB 写入）→ 落盘 `%APPDATA%/LocalToolbox/clipboard_images/` → 历史；
- 历史：条目 `kind=image`，桥层附带 160px 缩略图 data URL 与落盘路径；点击缩略图经 `clip_copy_path` 回贴；
- 回声抑制：接收内容哈希本地重算后进带 60s TTL 的 `_suppress` 表，监听读到同一内容自动跳过，过期自动清理；

## 十七、网盘挂载（v3.0，OpenList + WebDAV）

### 17.1 目标与路线

打通主流网盘（阿里云盘 / 百度 / 夸克 / OneDrive / Google Drive 等 40+）的统一访问：
托管 **OpenList**（自托管聚合程序）为统一后端，输出标准 WebDAV 接口；应用内置
纯 stdlib WebDAV 客户端完成浏览 / 上传 / 下载 / 建目录 / 删除 / 重命名；支持一键映射本机盘符。

选型理由：各家网盘 API 互不兼容且易变动，逐家自研网关脆弱且工作量巨大；OpenList 单实例
即可覆盖 40+ 驱动，且零新增 Python 第三方依赖（WebDAV 客户端为 stdlib 实现）。

### 17.2 功能

- **进程托管**（`openlist.py`）：探测 / 自动下载二进制 → `start(host, port, fw)` 拉起进程 →
  健康探活（对 `/dav` PROPFIND，≤30s）→ 防火墙放行 → 退出监控线程（3s 轮询，
  挂掉自动复位状态并记日志）；`stop()` terminate + kill 兜底 + 移除防火墙；
- **二进制自动下载**（`bindl.py`）：GitHub Releases 最新版 ZIP 模糊匹配 + sha256 校验 +
  `bindl/cache.json` 版本缓存，重复下载直接跳过；进度经 `pan_task` 推送；
- **驱动配置**（D2 边界）：不直接写 OpenList SQLite——网盘授权走两条路径：
  ①「打开管理界面」在浏览器完成授权；② 导入已有 `openlist.json`（`pan_import_config`，
  校验 `version` 与驱动数组后落盘 `DATA_HOME/openlist/openlist.json`，重启生效）；
- **文件操作**（`webdav_client.py`）：PROPFIND 列表（目录优先 + 空间配额）/ MKCOL /
  DELETE / MOVE / PUT 流式上传 / GET 流式下载，64KB 分块 + 进度回调；401/403/404/409
  错误统一中文提示；路径 URL 编码（中文/空格/`#`）并拒绝 `..` 穿越；
- **盘符映射**：`pan_map_drive(letter, user, pwd, persistent)` 经 `net use` 将
  OpenList WebDAV 挂载为盘符，`pan_unmap_drive` 取消，`pan_mapped` 列出已映射；
- **UI**（「网盘挂载」页，group=网盘与代理）：
  服务卡片（启动/停止/端口/健康状态/已配置驱动数）+ 文件浏览器（面包屑 + 表格 +
  上传/下载/新建目录/重命名/删除）+ 任务列表（进度/取消）+ 盘符映射区。

### 17.3 设计边界

- 文件传输任务限两个并发（ThreadPoolExecutor max_workers=2），逐任务可取消；
- WebDAV 每操作独立连接（urllib 非线程安全），线程安全由桥接层池化保证；
- 上传/下载目标路径经 `_safe_rel`-式校验，禁止越出当前挂载根。

### 17.4 功能扩展（v3.2）：Rclone 本地挂载 / 服务管理 / 更新 / 自启动

按「OpenList 功能特性（v3.2）」清单补齐服务治理能力：

- **Rclone 本地挂载**（`rclone_mount.py`）：把 OpenList WebDAV 挂载为**盘符**（`--network-mode`
  免管理员 + `--volname` 卷标，字母 A~Z 且未被占用）或**文件夹**（绝对路径，自动创建）；
  配置 `rclone.conf` + 日志落 `openlist/`；挂载 10s 探活（进程存活 + 挂载点出现），
  失败 terminate 并给日志尾部提示；卸载优先 `rclone umount`、兜底 terminate/kill；
  `list_mounted` 自动清理退出进程；`rclone.exe` 自动探测 + `bindl` 自动下载；
- **WinFsp 驱动**（`winfsp.py`）：检测（注册表 + 安装目录双路）；安装——管理员静默
  `msiexec /quiet /norestart`，非管理员 `ShellExecuteW("runas")` 触发 UAC 提权；
  `bindl` 支持 winfsp 裸 MSI 下载（落盘 `winfsp.msi`）后一键安装；缺驱动挂载报中文原因；

- **更新管理**（`bindl.latest` / `cached_version`）：查询 GitHub 最新版本与本地缓存版本，

- **自启动**（`config.py` / `bridge.py`）：三档——① 本应用开机自启（HKCU `Run` 键，

  winfsp_status / winfsp_install / set_autostart / rclone_state / rclone_set_cfg /
  rclone_mount / rclone_umount；js_api 清单 157 → 168。

## 十八、V2rayN 代理管理（v3.0 起，v3.1 升级三核心 / TUN / 规则库 / 高级路由 / PAC / 流量统计）

### 18.1 目标

导入 V2rayN 节点（订阅 / 配置目录 / 分享链接），应用内自跑 v2ray/xray 核心，
托管系统代理，监控连通性并失败自动切节点重连——「自动重连」在核心层面实现，
不依赖 V2rayN 客户端进程。

### 18.2 功能

- **节点导入**（三种方式，`v2ray_core.py` `import_sub_url / import_text / import_dir`）：
  ① 订阅 URL（base64 编码的 vless:// vmess:// trojan:// ss:// 行，`urllib` 拉取 + 解码 + 解析；
  vmess 按 base64 JSON 解析并读取 ps/add/port/id/net/host/path/tls/sni/flow/fp/grpcMode 等字段，
  解析失败的单条跳过并计数）；
  ② V2rayN 配置目录（`guiNConfig.json` 的 `vmess` 数组 + `configN.json` 的 vless/trojan 出站）；
  ③ 剪贴板 / 文本中的分享链接；节点库落盘 `DATA_HOME/proxy/nodes.json`（`NodeStore`）；
- **核心托管**：`detect_bin` 探测顺序 = 配置 `v2ray_bin` → `DATA_HOME/proxy/xray.exe|v2ray.exe`
  → V2rayN 安装目录；启动即写生成运行配置（inbound HTTP 10809 + SOCKS5 10808 +
  所选节点 outbound），`Popen` 拉起，经本地 HTTP 代理探活（≤20s，进程早退/超时即报错终止）；
- **系统代理托管**：仅运行期间写 winreg HKCU `Internet Settings`
  （ProxyEnable=1, ProxyServer=127.0.0.1:10809）；`stop` / 异常 / 关闭应用均还原原值；
  启动前清理指向 127.0.0.1 的残留设置；
- **健康监测与自动重连**：监控线程每 5s 经本地 HTTP 代理探测真实外网连通性
  （多探测源，任一可达即健康，延迟 `proxy_test` 实时回报）；连续 2 次失败触发
  自动切换下一节点重启核心（`_switch`），全部节点不可用时停止并还原系统代理
  （可关 `auto_switch`）；
- **桥接 API**（`proxy_api.py`，`proxy_` 前缀 25 个方法）与页面「代理管理」：
  核心程序选择 / 自动下载 xray、节点导入三入口 + 列表（测试 / 设为当前 / 删除）、
  端口配置、启动 / 停止、失败自动切换与系统代理开关、实时日志与状态推送。

### 18.2.1 v3.1 高级特性（对齐 v2rayN wiki）

- **三核心切换**：`xray / sing-box / v2ray` 三核心（`v2ray_core.py` 核心常量 + `build_core_config`
  分派）；sing-box 配置独立生成（`build_singbox_config`）；配置 `v2ray_core`；
- **代理模式**：`global` 全局 / `smart` 智能分流（国内 + 局域网直连，其余走代理）/
  `direct` 直连（= 停止核心）；配置 `v2ray_mode`；Xray 系与 sing-box 各自生成路由规则；
- **TUN 模式**：仅 sing-box 支持，需管理员权限（`_is_admin`）+ `wintun.dll`
  （随 sing-box 压缩包自动解出）；tun inbound（auto_route + strict_route，stack=mixed）；
  配置 `v2ray_tun`；
- **GeoIP / GeoSite 规则库**：`bindl` 支持两类规则库下载——Xray/v2ray 用
  Loyalsoldier/v2ray-rules-dat 的 `geoip.dat` / `geosite.dat`；sing-box 用
  2dust/sing-box-rules 的 `geoip.db` / `geosite.db`（wiki 指定来源）；
  sing-box 路由经 `route.geoip/geosite.path` 指向规则库，`geoip:private/cn`、
  `geosite:cn`、`geosite:category-ads-all` 分流；规则库缺失自动退回内置静态规则；
  规则库下载入口 `proxy_download_geo(core?)`；
- **高级路由 / DNS 编辑**：`advanced.json` 持久化，routing 支持 v2rayN 自定义路由规则数组
  （`_xray_rules_from_v2rayn` / `_singbox_rules_from_v2rayn` 转换，`geoip:/geosite:` 前缀
  映射到 sing-box `geoip/geosite` 字段，空规则过滤）或对象整体覆盖；dns 对象合并；
  下次启动生效；`proxy_get_advanced` / `proxy_set_advanced`；
- **系统代理四策略**（wiki「系统代理和路由说明」）：`auto` 自动配置（启动写入、停止还原）/
  `pac` PAC 模式（`AutoConfigURL` 指向本地 `pac.js`：本机/局域网 DIRECT，其余 PROXY 核心）/
  `none` 不改变 / `clear` 清除；运行中可即时切换；配置 `v2ray_sysproxy`；
- **流量统计**：`traffic.py` 经 PowerShell `Get-NetAdapterStatistics` 系统级采样实时速率
  （三核心通用、无额外依赖），前端实时速度条，`proxy_traffic` 事件推送；
- **批量测速**：`proxy_burst_test` 并发（上限 3）测全部节点延迟，按延迟排序返回并回写
  节点库 `latency`；前端展示排序结果。

### 18.3 安全

- 节点库与生成配置仅含本机可读的代理参数，不落任何口令字段；
- 系统代理还原在 stop / 异常 / 应用退出三处兜底；残留检测仅清理明确指向 127.0.0.1 的值；

## 二十一、ShareX 式截图能力增强（v3.3，参考 https://github.com/ShareX/ShareX）

参考 ShareX 补齐四项截图配套能力，落地到既有「工具 → 截图标注」页与「工具箱」页
（无新增导航页面，不改变 15 页结构）。

### 21.1 区域截图

- **方案**：前端遮罩层（`webui/js/pages/region_capture.js`），后端仅回送全屏 PNG——
  规避 pywebview 透明窗口在跨显示器下的行为差异；
- **流程**：`shot_capture_region`（后端全屏捕获）→ 遮罩拖选（实时 x/y/w/h 尺寸栏 +
  放大镜预览选定区）→ 确认裁剪出选区 data URL → 载入既有共享画布编辑器
  （标注 / 保存 / 复制 / 发到剪贴板历史全部复用）；Esc / 右键取消；
- **坐标换算**：按设备像素比（window.devicePixelRatio）统一，宽高四舍五入防亚像素错位。

### 21.2 GIF 屏幕录制

- **采集**（新增 `app/core/recorder.py` `RecorderManager`）：守护线程按帧率
  （2 / 5 / 10 fps 白名单）轮询 `PIL.ImageGrab.grab()` 累积帧列表；
  `MAX_FRAMES=1200` 自动停止（防内存失控）；采集循环内约每秒节流回调状态；
- **停止与编码分离**：`rec_stop` 仅置位事件立即返回；采集循环退出后在**采集线程内**
  编码与保存并回调 `rec_done`（js_api 调用线程不被编码耗时阻塞）；
- **保存策略**（`screenshot.save_frames`）：帧数 ≥2 且首帧 PNG ≤1.4MB → GIF
  （`disposal=1` 全幅覆盖逐帧替换、`duration≥50ms`、`optimize`、loop=0），
  否则退化单张 PNG；沿用日期子目录 + 重名序号命名 `{日期}_{时间}_rec.gif|png`；
- **桥接**：`rec_start(fps?)` / `rec_stop` / `rec_get_state` / `rec_set_fps(fps)`；
  事件 `rec_state`（~1/s 节流）与 `rec_done`（含路径/帧数/大小/类型）；
  配置 `recorder_fps`（默认 5）。

### 21.3 OCR 识别文字

- **引擎**：系统原生 `Windows.Media.Ocr`（`winrt-Windows.Media.Ocr` +
  `winrt-Windows.Graphics.Imaging` 绑定），本地识别、无网络上传；中文识别依赖
  系统已安装 `zh-CN` 语言包（`OcrEngine.get_available_recognizer_languages` 匹配，
  兜底 `try_create_from_user_profile_languages`）；
- **依赖降级**：`is_available()` 惰性探测，缺失时入口直接报中文提示
  （「OCR 组件不可用：请安装 winrt 依赖或系统语言包」），绝不崩溃；
- **识别**：PIL Image → `SoftwareBitmap`（`BitmapDecoder.create_async` →
  `get_software_bitmap_async`，Bgra8/Premultiplied）→ `OcrEngine.recognize_async`，
  `_block_on()` 包装异步；输出全文 `text` + 逐行 `{text, rect{x,y,w,h}}`；
- **入口**：截图页画布「OCR 识别文字」（`shot_ocr(data_url)` 识别当前画布图）与
  工具箱「OCR 识别图片」（`tool_ocr_file` 文件选择框）；结果经 `ocrResultModal`
  弹窗展示（全文一键复制 + 逐行点击复制 + 坐标/尺寸）。

### 21.4 屏幕取色器 + 放大镜

- **切色格式**：`rgb_to_hex` 三通道钳位 0–255 后大写字符合成 `#RRGGBB`。

### 22.2 关键实现说明

- **DPI 根治**：main.py 入口最先调 `enable_dpi_awareness()`——未声明 DPI 感知时

- **任务链时序**：捕获 → 保存原图 → 复制剪贴板 → 按 edit 推送 shot_pick /
  shot_capture_done（edit=false 仅 toast 不跳页）；保存/复制的对象是**选区原图**
  （与 ShareX 一致：任务链先于编辑器）。
