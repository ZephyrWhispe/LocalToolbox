## 用户场景

多台 Windows 局域设备间频繁使用 SMB / FTP / WebDAV 账号访问，
每台设备需人工记忆或重复输入同一组凭据；密码散落在各类工具（浏览器、
远程挂载）与笔记中，难以统一管理与轮换。

## 期望行为

- 提供「密码管理」页：凭据条目标记 `名称 + 目标(host/地址) + 用户名 + 密码`；
- 密码加密存储（复用 DPAPI + AES-256-GCM 方案，参考剪贴板历史加密）；
- 可在 SMB / FTP / WebDAV 连接表单中「从密码库填入」，一键填充账号口令；
- 凭据按需导出/导入（加密容器）或仅限本机使用（默认）。

## 现状

- `app/core/pairing.py` 已有 EncryptedChannel（AES-256-GCM）可复用；
- 剪贴板历史加密（v2.9, T-02）已落地 DPAPI 保护密钥模式；
- FTP / WebDAV / SMB 连接均为表单手动输入，无凭据记忆。

## 影响面

- 涉及模块：新增 `app/core/vault.py`（估）+ `app/bridge/vault_api.py` + `webui/js/pages/vault.js`；
- 配置：新增 1 个开关（如 `vault_enabled`，默认关）；
- 无新端口；数据落盘 `%APPDATA%/LocalToolbox/vault.db`（加密）；
- 安全面：凭据类数据安全特性要求高，涉及加密、脱敏、审计日志。

## 关联

- 未完成与中断任务清单 T-08；
- 复用：clip_store_key 的 DPAPI 密钥模式、pairing.EncryptedChannel。
